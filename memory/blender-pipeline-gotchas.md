# Blender model pipeline: how to rebuild, and the traps already hit

The game's 3D models are generated by scripts in `tools/blender/` (shared kit
`paintkit.py`, one `create_*.py` per asset) into `models/generated/*.glb`.
Rebuild all: `tools/blender/build_all.sh [preview_dir]` (~35 s). Then import
with the Godot exe: `--headless --path <proj> --import`.

Traps, each of which cost a debugging round on 2026-09-30:
- In Python, `obj.matrix_world` is stale until the view layer updates. Reading
  it right after setting `location`/`rotation_euler` (e.g. to parent without
  moving) silently throws the rotation away. paintkit's `parent()` and
  `set_origin()` call `bpy.context.view_layer.update()` first - keep it.
- Blender exits 0 even when a `--python` script raises, unless you pass
  `--python-exit-code 1` (build_all.sh does).
- Blender 5's `shade_smooth_by_angle` keeps edges already marked sharp; a
  second call with a wider angle does nothing. Use
  `shade_smooth(keep_sharp_edges=False)` to fully soften.
- `join()` keeps the first part's transform; bake it before editing vertices.
- Materials export `doubleSided` unless `use_backface_culling` is on; paintkit
  turns it on by default.
- A character facing Blender -Y has its RIGHT side on -X. (I got this backwards
  in a spec; the subagent caught it.)
- glTF keeps object names as Godot node names and material names as
  `resource_name`, which is what the runtime recolour relies on.

Why: recorded so a later session does not rediscover these one at a time.

How to apply: read before touching any `tools/blender/` script. Check every
model with `--preview <png>` (a 2x2 contact sheet) before importing. See
[[commands-for-jarmans-terminal-use-full-paths-no-bang]] for the numpy
prerequisite.
